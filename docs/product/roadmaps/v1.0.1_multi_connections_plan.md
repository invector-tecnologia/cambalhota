# Roadmap v1.0.1 - Multi-Connections & TUI Refinement

## Visão Funcional Detalhada
A versão 1.0.1 do Cambalhota introduz o gerenciamento de conexões diretamente via interface de usuário (TUI), eliminando a necessidade de variáveis de ambiente. O foco principal é viabilizar o cadastro de múltiplas fontes de dados e permitir a migração de dados cruzada (backup de uma origem e restore em outro destino) de forma fluida.

### Requisitos de Negócio Atendidos:
1. **Configuração via TUI:** Eliminação de `.env` para credenciais. Toda configuração passa a ser visual.
2. **Armazenamento Seguro:** As credenciais serão persistidas em um arquivo local SQLite (`~/.cambalhota/connections.db`), protegidas via criptografia AES-256 (padrão do produto).
3. **Múltiplos Bancos de Dados:** Suporte a gerenciar N conexões em paralelo.
4. **Backup e Restore Cruzado (Cross-Database):** Capacidade de extrair de um banco (Origem) e restaurar em outro (Target).
5. **Identidade Visual:** Inclusão de Logo/Nome "Retrowave" em ASCII Art no canto superior esquerdo da TUI.

## Jornada do Usuário (TUI)
1. **Acesso Inicial & Logo:** Ao abrir o Cambalhota, o usuário visualiza no canto superior esquerdo a logo em ASCII Art no estilo "Retrowave".
2. **Aba "Gerenciar Conexões":**
   - O usuário navega até a nova aba de conexões.
   - Pressiona um atalho (ex: `Insert` ou `[Nova Conexão]`) para abrir o formulário.
   - Preenche os dados: Nome, Tipo do Banco, Host, Porta, Usuário, Senha e Schema.
   - A senha é mascarada. Ao salvar, o sistema criptografa usando AES antes de gravar no SQLite.
3. **Aba "Backup & Extração":**
   - O usuário seleciona a conexão de "Origem" (Source) através de um painel de seleção.
   - Executa a extração. O sistema usa as credenciais armazenadas para conectar e gerar o dump.
4. **Aba "Restore & Importação":**
   - O usuário visualiza os dumps disponíveis localmente.
   - Seleciona o arquivo de dump.
   - Seleciona a conexão de "Destino" (Target) a partir das conexões salvas.
   - Confirma a operação, realizando o restore cruzado.

## Critérios de Aceite
- [ ] A aplicação não deve exigir/ler variáveis de ambiente para credenciais de banco.
- [ ] A aba "Conexões" deve permitir CRUD completo de bancos.
- [ ] O banco de dados SQLite local deve armazenar a senha de forma criptografada (AES).
- [ ] O sistema deve permitir a execução de Dump e Restore utilizando origens e destinos diferentes.
- [ ] A Logo Retrowave (ASCII) deve ser exibida globalmente no header superior esquerdo da TUI.
