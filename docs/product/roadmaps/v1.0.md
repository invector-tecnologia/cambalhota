# Roadmap v1.0 - Cambalhota

## Business Vision: Objective, Transparent and Safe Operation
Cambalhota version 1.0 embodies the core product vision: the irrevocable commitment to create, run and manage backups of database schemas, their tables and their data in a fully *fail-safe* way. 

The entire operation must be objective, transparent and safe. The end user (developers, DBAs, SysAdmins) can make operational or modeling mistakes with the peace of mind of knowing that **they can always recover the state before the mistake, without losing their data.**

## Version 1.0 Scope (Must-Have)
Prioritization for v1.0 follows the MoSCoW matrix, covering only the "Must-Have" features set out in the PRD, spanning Epics 1, 2, 3 and the structural base of Epic 4, together with the mandatory interface (Epic 5).

### Epic 1: System Configuration and Connection
- **Feature 1.1: Connection Management:** Allow secure connection to the managed databases.
- **Feature 1.3: Project Preferences:** Parameterization of the system's behavior.

### Epic 2: Extraction (Backup) and Persistence
- **Feature 2.1: Structured Extraction:** Perform a full dump of metadata, schema and data in a predictable and isolated way, adopting a multi-engine architecture based on standard CLI utilities (agnostic to the database technology). The backup will be encrypted by default and persisted on the local disk in `~/.cambalhota/db_dumps/YYYY/`.

### Epic 3: Restore
- **Feature 3.1: Local Listing and History:** Quick view of the encrypted backups available locally in `~/.cambalhota/db_dumps/YYYY/` and their respective timestamps.
- **Feature 3.2: Full Restore (Fail-safe):** Full recovery of the environment (schema, tables, data) from the local backups, letting the user revert any critical error instantly.

### Epic 4: Migration Engine (Structural Version Control) - Base
- **Feature 4.1: Flyway-like Migration System:** Generation of standardized upgrade and rollback scripts (up/down).
- **Feature 4.3: Transactional Execution and Concurrency Protection:** Locks and safe transactions to prevent schema corruption during parallel executions.
- **Feature 4.4: Integrity and History Audit:** Rigorous tracking of applied structural changes to make drift detection easier.

### Epic 5: Terminal User Interface (TUI)
- **Feature 5.1: Standardized TUI Experience:** The terminal interface is the embodiment of the Cambalhota vision. The product vision must be fully converted into the user's perception. The TUI must convey in a tactile way the **objectivity**, the **transparency** of everything that happens behind the scenes, and the **safety** that every action has a guaranteed way back (fail-safe).

*(Note: Feature 4.2 - Structural Diffing and Epic 6 - Documentation and Technical Utilities were classified as Should-Have / Nice-to-Have in the PRD and are postponed to v2.0).*

### Next Steps (v2.0 Vision)
Based on the competitive analysis against utilities such as WAL-G and pgBackRest, the future evolution of Cambalhota will focus on storage integrations and external uploads.
- **Repository/CDN Integration (Features 1.2 and 2.2):** Ensure that the backup is stored remotely in a safe, redundant cloud location.
- **Payload Optimization (Feature 7.2):** Implementation of stream compression for later upload to the CDN, saving storage and bandwidth.
